# What `sys/sys.b` does not bind

`sys/sys.b` is `beansc bindgen` output over `vendor/postgresql/src/interfaces/
libpq/libpq-fe.h`, regenerated by `tools/regen_sys.sh`. It binds **199 of the
202 declarations** in that header.

## The three it skips

All three are the same thing: libpq's deprecated *fast-path function call*
interface.

| declaration | why bindgen refuses it |
|---|---|
| `PQArgBlock` (record) | holds an anonymous `union { int *ptr; int integer; }`. bindgen has no spelling for an anonymous record, and it omits rather than invents. |
| `PQArgBlock` (again) | the same record reported for its unnamed member type. |
| `PQfn` | takes a `PQArgBlock *`, so it cannot be bound while the record cannot. |

`PQfn` is the protocol-level fast path that `fe-lobj.c` uses internally for
large objects. Upstream documents it as for internal use, and nothing in this
package's public API reaches it. The vendored `fe-lobj.c` still compiles and
still calls it **inside C**; only the Beans binding is absent.

## What that costs

Nothing this package offers. Large objects are not in the v1 API either (see
the README), and `bytea` covers what most callers want a large object for. If
a real request for `lo_*` arrives, the way in is a small flat-ABI shim beside
`src/` — an integer handle in, an integer out, no struct crossing by value —
not a change to the generated file.

## What is bound but not used

The generated file carries the whole libpq surface, including entries this
package's Beans API never calls (`PQtrace`, `PQsetdbLogin`, the
`PQconninfoOption` walkers, the deprecated `PQexec` family). They cost nothing
— an `extern "C"` declaration emits no code — and having them there means a
caller who needs one does not have to regenerate anything.
